## 四、门禁的四条定性（读代码前先看这段，否则会误用它的读数）

> ⚠ **适用范围（第二十五批补，不补就会被当成全部门禁的定性）**：下面四条说的是**文本形状类门禁**（`check-tokens.mjs` 与同族的 `check-events.mjs`）。
> 本批新增的 `verify-sse.mjs` 故意不在这四条里 —— 它就是「没有一条锁行为」那句话所指的那一层（工单件 §10.5 的第 ① 层），
> 两层互替不了；拿本节四条去读行为件会得出相反结论。

1. **全部是脆断言**：`readFileSync` + 正则的文本形状断言，只锁结构不变量（令牌登记、双向覆盖、
   dark 双写同值、字典 key 集 == 从源派生集），**没有一条锁行为**。不断言「route 事件渲染出来是蓝的」。
2. **扫描面含注释**：断言 1 扫全文，所以注释里举 hex 反例会被自己的门禁判红（POC 实踩两次）。
   处置口径：解释性文字只引比值与令牌名，hex 明细进取证档。这不算放宽断言。
3. **行尾已归一**：所有读取走 `readText()`（`\r\n → \n`）。POC 首跑实踩：断言 5 的锚点写了字面
   `\n }\n}`，在 Windows checkout（CRLF）上失配 ⇒ **同一份门禁在 LF 环境绿、CRLF 环境红**，
   判据随检出平台漂移就等于不可复现。
4. **读不到源就 fail（有意的 fail-closed）—— 但这句只对一口成立，现已逐口实取**。断言 6 的两个期望集现在从**两个不同文件**读（事件字典在
   对话页、灯阵字典在独立页）。拆页时这里实踩过一型：灯阵字典住到第二页后，旧锚点读不到它 ——

   「坐标变了，先核对再改门禁」）。口径：**门禁查不到被检物 = 红，不是抛异常也不是静默跳过**。
   ⚠ **第六批拿两格探针实测：这句只对 `LAMP_GROUPS` 一口成立**；**第七批把剩下三口也逐口剖了**（变异只打在镜像树副本上，产品源一个字节未动）：

   | `dictKeys` 事件字典 | 重命名 `const EVENTS` | 1 | **全空** | check-tokens.mjs 第 165 行抛错（第六批实取） |

   | `healthFields` 第二层 | 改 agent_server 侧 class 头 | 1 | **全空** | 「…schemas.py 里找不到 class HealthResponse」（栈点第 138 行） |

   ⇒ **四口全为运行时读数，不再靠读代码推定**；正对照那一行是关键 —— 它排除掉「探针自己没能力捕获失败」这一解释，所以「stdout 全空」能归因到 throw 而不是归因到探针。**rc 不是可分的读数**，能分的只有「有没有那段失败清单」。
   本目录**未改这三口**（属开新方向），只登记在册，处置待拍板（取证件 §13.5 / **§14.2**，镜像树方法与基线自证在 **§14.6**）。
