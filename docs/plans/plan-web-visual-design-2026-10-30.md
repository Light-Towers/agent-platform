### 1.2 令牌分三层（结构借 Radix Colors 的实测形状，见 §4 第 3 项）

| 层 | 内容 | 谁可引用 |
|---|---|---|
| **L0 primitive** | `--n-050…--n-900`（中性 9 档）+ 8 个色相档（`--blue-600` / `--cyan-600` / `--green-600` / `--violet-600` / `--teal-600` / `--amber-600` / `--red-600` / `--slate-600`，dark 侧取 `-300` 档） | **只有 tokens.css 内部**；组件引用 L0 = 门禁红 |
| **L1 semantic** | `--text-1/2/3`、`--bg-page/surface/raised`、`--border-decor/control`、`--status-ok/warn/danger/running`、`--cat-*`、`--tint-*`、`--focus-ring`、`--shadow-1/2`、`--sp-*`、`--fs-*`、`--lh-*`、`--ls-*`、`--radius-*`、`--t-*` | 组件唯一可消费层 |
| **L2 alias** | 同值别名必须**显式命名**（`--cat-terminal: var(--status-ok)`、`--cat-failure: var(--status-danger)`） | 让图例读得出「这一族共用一个值」，而不是偷偷复用 |

不写 `rgba()` 进组件：所有带透明度的底做成语义令牌（`--tint-*`），这是从 Radix 把 alpha 变体单列成 `blackA/whiteA` 两组令牌的做法直接搬过来的**形状**（搬形状不搬色值）。

**L0 的「档号 ↔ 用途」映射（实现期不得猜该拿哪一档）**：`050–100` 页面底与卡片底 · `200–300` 分隔与填充 · `400–500` 加重分隔（`--border-decor` 落此） · `600–700` 控件边界与实心控件（`--border-control` 落此） · `800` 次要正文（`--text-2/3`） · `900` 主要正文（`--text-1`）。⚠ **口径说清**：借来的是「同一档号在 light/dark 服务同一用途」与「dark 是**重取不是反色**」这两条**纪律**（出处：证据件 §11.2 第 1 项 —— Radix dark slate 从 `#111113` **递增**到 `#edeef0`，而「12 恒为正文」这个不变量全程保住）；而**具体哪六段对哪个角色、以及本件为何用九档而非十二档，是自定**（§1.3 只需三档文本 + 三档底色）。本批**不重排 L0 的档数**，只补上角色映射。

### 1.6 主题机制（深浅两案的底线要求）

```
:root                                    { /* light 全量 */ }
@media (prefers-color-scheme: dark) { :root:not([data-theme]) { /* dark 全量 —— 副本 A */ } }
:root[data-theme="dark"]                 { /* dark 全量 —— 副本 B，必须与 A 逐字同值 */ }
:root[data-theme="light"]                { /* 回到 light */ }
```

- 默认**跟随系统**（`prefers-color-scheme`），手动切换写 `<html data-theme>` + `localStorage['ap.ui.theme']`。主题偏好**不是凭据** ⇒ 与工单件 §2.3 那条「密钥只存内存、不落 localStorage」不冲突；这条边界写在这里，免得后人拿密钥纪律误伤主题键。
- 无 SSR ⇒ 首帧由 CSS 媒体查询保证（不闪烁）；手动偏好由 `main.ts` 读取，代价是**切换时可能有一帧闪烁**，属已知取舍（要消除它就得往 `index.html` 塞内联脚本，本件**不做**：`index.html` 是被 no-store 锁着的壳，塞脚本等于给自己加一条 CSP/审计面）。
- 两处 dark 声明「逐字同值」不是散文约定，是门禁断言 5（§6）——这是这类双写最常见的腐坏方式。

**硬规则（三条，都是 POC 实测逼出来的，不是审美偏好；出处 = 取证件 §12）**：

1. **任何 `fr` 轨道必须包进 `minmax(0, …)`。** `1fr` 的默认最小值是 `auto` = min-content ⇒ 裸写会被内容顶破：POC 实测三栏 `1.1fr 1.4fr 1fr` 在含长 token 时崩成 **219 / 279 / 822**，比例 1.1:1.4:1 完全失效。比例可以继承参照物，**写法必须显式**，否则继承来的是「比例失效」。
2. **`auto-fill` 网格的列数由它自身容器宽度决定，与视口无关。** 因此断点表里凡写「N 列」，必须同时写明**这个 N 受哪个容器约束**；不写明就会犯本节上面那个错（把 3 列排进一条 `1fr` 轨道）。本表视图 B 之所以不再写各视口列数，就是为了消掉这一类被误读为「已处理窄栏」的空话。
3. **同一选择器的默认值与断点覆盖必须同文件、且覆盖在后。** POC 实踩：`.lamps` 的断点写在 `base.css`，而 `events.css` 在其之后加载 ⇒ 同特异度下那条覆盖**从未生效过** —— 写了等于没写，还让人以为窄栏已处理。

窄栏折叠（768–1279 的 `<details>`、<768 的计数徽标）这一取舍有参照出处：证据件 §7 判据 1 —— Langfuse 的 trace 时间线同样靠「可折叠行 + 逐层组件」读层级，不用连接线。

### 2.2 时间线：12 类事件的分色与图例

每一项 = **3px 左边框 accent + 类型徽标（mono，永远显示事件名原文）+ 正文**。徽标文本用 `--text-1`，accent 只上色到边框与图标（§1.3 规则）。事件名原文常显 ⇒ 同时满足工单件 §2.2「未识别事件不得静默吞掉」与「色彩不是唯一通道」。

**（第五批把上面那条从「规则」升级为「带算式的判据」，F2/F3）**：

- **族色不得进文字通道。** 实测 12px mono 徽标文本若着族色：light 侧最弱一组 **3.25:1**、dark 侧 **4.25:1**，两者都低于正文 AA 的 **4.5:1**（不是低于 3:1 —— 文字通道按 4.5 判，3:1 只适用于图形与控件边界，SC 1.4.11）。所以「accent 只上色到边框与图标」不是风格选择，是**对比度预算决定的**：竖条与图标走 3:1 那一档，族色满足；文本走 4.5:1 那一档，族色不满足。
- **前景色必须按它实际所在的底版重算，不得沿用页面底色上的读数。** 实踩：`--text-2` 在页面底色上合格，落在**失败 tint 底版**上只有 **4.14:1** ⇒ tint 底版上的次级文本要么提级到 `--text-1`，要么为该 tint 单独登记一枚前景令牌。**每张 tint 都要重算一遍**，这是一条一次性成本，不是一次性结论（换底色或改 tint 透明度就作废）。

|---|---|---|

灯卡形态（`LampCard.vue`）三段，**第一段就是可追溯性本身**：

1. `字段名原文（mono） = 接口读到的原始值`（逐字打印，不做本地推断 —— PR-4 原判据）
2. 一句人话说明，来自**纯展示字典**（key 必须是派生字段名，value 只是文案；字典由门禁断言 6 校验 key 集，因此不会漂出「有字段没灯」）
3. 状态点**四档形状**（第五批按实测从「三档」扩为四档，算式见下 ⚠）：`true` → `--status-ok` **实心圆** · `false` → `--text-2` **空心圆** · `null` / 未定义 → `--status-warn` **实心圆（警示色）** · **非布尔值**（字符串 / 对象）→ `--text-2` **空心方块**。字符串仍按值着色（`ACTIVE`→ok、`DEGRADED`→warn、`DISABLED`/`UNINITIALIZED`→muted），但**色只是二次强化，第一通道是形状**。
   四档的意义：`false`（未启用）与 `null`（未装配）**必须是不同形状**，否则「接线 ≠ 启用」这条 AGENTS.md 红线在界面上被抹平 —— 这是灯阵唯一硬性的语义要求。第四档不新增语义，它防的是「非布尔值着色成 warn 实心圆后与 `null` 同形」：`DEGRADED`（装配了、降级运行）与 `null`（根本没装配）是两类事实，共用一套形状就是把红线又抹回去一次。
   ⚠ **形状通道的最小可辨量（F7，第五批实测推翻本件上一版的修法）**：空心圆与空心方块**只差圆角时不算两个形状**。状态点是 10×10px，`--radius-pill 999px` 在这里被钳制为 **5px**（盒子内切半径上限 = 短边的一半），而 `--radius-sm` = **4px** ⇒ 两档实际只差 **1px = 边长的 10%**，不可辨。判据落成一句：**要进形状通道，圆角要么取 0（方）要么取内切（圆），不接受中间值** —— 中间值看着像两个值，渲染出来是同一个。

⚠ 一处**对参照物的刻意偏离**（得记在案，不能让读者去比对时自己猜）：`console.html:35-38` 的灯是四档 `dim/on/off/warn`，其中 `off` 涂 `--bad`（红）。本设计不继承那一档：红是失败色，**未启用不是失败**。继承的是 `on`（`--ok #0a7d33`）与 `warn`（`--warn #8a6100`）两档的色值。出处与理由见证据件 §5「修正二」。

⚠ 两个「四档」不是一回事，别让下一批读混：参照物的四档是**四个语义**（dim/on/off/warn），本件第四批起说的是**四个形状**（实心圆 / 空心圆 / 警示实心圆 / 空心方块）。扩的是**通道**，不是往语义上加档 —— 「接线 ≠ 启用」那条红线仍只有 `false`/`null` 两态承担。

## 6. 视觉门禁（三层齐备 + 非空转反证表）

按 AGENTS.md《架构决策原则》，样式层要「单一实现 + 全局装配 + 强制门禁」三层齐备才算全局解，否则只是散文约定：

- **单一实现**：`tokens.css` 是全工程唯一出现 hex/rgb/rgba 的文件（§1.1/§1.2）。
- **全局装配**：`main.ts` 单入口按序 import 三个样式片段（§1.1）；组件不自行引样式，漏装的症状是「完全无样式」而不是「样式漂了」——可立即发现。
- **强制门禁**：`web/scripts/check-tokens.mjs`（零新依赖，Node 原生，与工单件 §10.5 已采纳的 `check-events.mjs` 同族），挂进 `make ci-web`（工单件 §5 已定形状；**不进 `make ci`**，保持 Python-only 机器可跑 `make ci`）。

六条断言：

1. `tokens.css` 之外任何样式与宿主文件不得出现 `#` 十六进制、`rgb(`、`rgba(`（PR-0 交付前的扫描面 = 样式三件 + **两个 POC 宿主页**；交付后换成 `src` 下 `.vue` 递归）；
