# 方案：门件从「工作区门禁」升级为「候选树门禁」+ 不碰共享索引的提交方式

> 批次：第三十九批（刀㊻）。状态：**待人批 → 批后本件即为实现说明书**。
> 触发源：连续三批（第三十六、三十七、三十八批）被同一件事挡在提交门外，且每批都要重新取证、重新解释一次。本件的目标不是"把这次的红绕过去"，而是**让这一型问题不再复发**。

## 1. 目标（一句话）

让「我这一刀能不能提交」这个问题，回答在它真正该问的载体上——**这个提交将造成的那棵树**，而不是"整条工作线上所有人此刻未完成的活"。

## 2. 根因（三条都是实测，不是推定）

| # | 事实 | 量法 | 后果 |
|---|---|---|---|
| R-1 | 产品基线是干净的：HEAD 那棵树全仓 lint 通过 | 把 HEAD 导成实体树再跑（944 个 .py 在盘上才算跑过；第一次用 PowerShell 管道传 tar 流把归档打坏了，那轮的 `All checks passed` 是空转绿、已作废） | 债在**未提交面**，不在基线 ⇒ 拿它卡提交门是卡错了对象 |
| R-2 | 门件的输入面 = 整个共享工作区 | 门件 A 格基准是 `git diff --name-only HEAD` | 另一条线未完成的活（含"import 已写、使用点未接"的 8 枚未用导入）永久挂在本刀门上，本刀无论怎么收尾都绿不了 |
| R-3 | A 格的基准看不见未跟踪文件 | 同一条命令 | 于是新文件进不了门：申报它 ⇒ `MISS-DECL`，不申报 ⇒ `UNTRACKED-FOREIGN`，两难唯一同时满足的形状是 `git add`；而 git 的索引是**两条线共享的**，一次批量 add 会把未过门的一方一起带走 ⇒ 在册已立"占面期间不得 stage" |

R-2 + R-3 合起来是个**死锁**：门要绿需要提交，提交需要暂存，暂存在共享索引上等于替别人做决定。所以这不是"再等等"能了结的，必须换机制。

## 3. 治本机制（三件，缺一退化成约定）

### M1 单一实现：候选树先行，提交在后

> ⚠ **本节载体已被实测推翻，正确载体见 §9 行 1**。保留原文是为了不让后人以为「临时索引」这条路没被走过：它走不通的原因可复核，不是偏好。

- 用一次性临时索引（`GIT_INDEX_FILE` 指向 gitignored 目录里的一份临时索引）从 HEAD 起树，只加本刀路径，`git write-tree` 得到候选 tree OID。
- **先拿这棵树过门，后才 `git commit-tree` + `update-ref`**：避免"先提交再补验证"这种把顺序倒过来的做法。
- 真索引全程零改动（开工前实测 `staged = 0`，收工后必须仍是 0，这一格是硬判据）。

### M2 全局装配：归属由两个 git 事实派生，不许人写

| 集合 | 定义 | 处理 |
|---|---|---|
| own | 出现在候选树里的改动文件 | 全判据照跑，任一红 ⇒ `GATE_RC=RED` |
| ext | 工作区面里**不在**候选树中的文件 | 逐条列出 + 计数入账，**不参与 rc**；同时全仓原始读数照打，不消音 |

两条反作弊齿，缺一条 M2 就退化成"想免责谁就划给 ext"：

- **T-a 偷带齿**：ext 中任一文件若出现在候选树里（即被划进我提交）⇒ 当场红。含义：想把别人的活带进来，就得连它的半成品债一起继承——B 格会立刻替我把它判红，归属作弊不可能成功。
- **T-b 逃逸齿**：本刀已申报为交付面、却没进候选树、又落在 ext 里 ⇒ 判 `OWN-NOT-COMMITTED` 红。含义：不许把自己的活悄悄推到"外部面"里去免检。

### M3 强制门禁：新齿必须自证能咬

- 门件自测加两枚合成样本（一枚偷带、一枚逃逸），**期望双咬**；自测数下限随之上调（现 10 枚 → 12 枚），下限由门件 B3 那格绑定，不靠文档承诺。
- 真面反证：在候选树里种一枚真实缺陷（借未用导入的形状）⇒ 门件必须红 ⇒ 按字节还原 ⇒ BYTE-EXACT 后复跑绿。

## 4. 为什么这不是"放宽前置条件凑绿"（红线自查）

1. **判据一条没减**：own 面的 lint / 结构 / 文档 / 测试全跑，且跑在**将入库的那份字节**上（导出树），比原来更严——原来跑的是工作区，测的字节和入库的字节可能不同。
2. **ext 不是删除项**：它逐条进账、逐轮计数，是一条可见的、有归属的外债台账；那条线落地之日就是它归零之时。
3. **不代人做决定**：不删别人未完成的导入、不改别人文件的一行、不暂存、不替那条线提交。
4. **免责是有条件的**：靠 T-a/T-b 两齿保证，而不是靠一个开关；开关式旁路（`--skip-x`）本方案明确**不设**。

## 5. 影响面

- 改：门件本体（新增 own/ext 派生段 + 两枚自测 + rc 组成调整）、一次性取证件（候选树导出/提交/复取）。
- 不改：`scripts/` 下入库 lint 工具本体、Makefile 的 CI 定义、后端产品代码、任何一条既有判据的阈值。
- 下游：CI 唯一门禁 `make ci` 不受本方案影响（它在 CI 里跑的是干净 checkout，天然等价于"候选树"）——这也是本方案成立的外部证据：**CI 早就按树跑，只有本地门件按工作区跑**。

## 6. 迁移与回滚

- 无数据迁移、无契约变更、无依赖新增。
- 回滚：门件改动字节还原即可；提交本身在推送前可原地丢弃（分支 ref 回到旧 OID，工作区不受影响，因为从未依赖暂存区）。

## 7. 验收（每条都必须给可核对的读数，缺一条即未达）

1. 真索引零改动：提交前后 `staged` 读数同为 0。
2. 候选树 lint 绿：导出的实体树里 .py 计数 > 0（防空转）后跑，rc=0。
3. own 面后端不变量（结构 lint）rc=0，且 ext 集合逐条列出的文件数 = 11（与本批开工读数一致）。
4. 两枚新齿合成自测双咬；门件自测数 n=12、passed=12。
5. 真面反证：种缺陷 ⇒ `GATE_RC=RED` ⇒ 字节还原 ⇒ 复跑 GREEN。
6. T-a 反证：把 ext 里某文件塞进候选树 ⇒ 门件必须当场红（不是"数变少了"）。
7. 提交后复取：本刀面在 `git ls-files` 内命中（此前两文件零命中那一格必须翻转），`ext` 文件仍不在任何提交里。
8. 推送前后按在册规矩：当天最终 rev 跑 L3，0 命中才推；非 force、不碰 main、不动公开镜像。

## 8. 明确不做（免得"治本"变成新一轮范围蔓延）

- 不删那 8 枚未用导入，不"顺手"替那条线补使用点。
- 不在本批引入 git worktree 隔离（备选，代价：`.venv` 与 node_modules 需重建、账面出现两套 rev 归属；M1–M3 已能解开死锁，先不上重手段）。 ⇒ **本条已推翻，见 §9 行 1**：不是选择问题，是六把 lint 工具的定根方式让「实体导出树 / 临时索引」两种轻载体必然 fail-closed 或空转绿。
- 不碰 126/241：通道实测 TCP 22 超时（网络层），Linux 侧半条链固定为挂起项，见 `docs/operations/nl2sql-release-checklist.md` 同级的发布 runbook，不再每轮重议。
- 不改 T2/T4 书写判据；但本批顺手把**键审计最大已知免检区**（一行多件名）从 7 降到 0，并给门件加棘轮下限——它属于同一型"别再发现新问题"的收口，不是新战场。 ⇒ **本项属未做**（登记在 §9 行 6，不充成本批交付）。
