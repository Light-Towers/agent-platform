# 节点时钟与取证时间戳可证性（2026-11-04）

状态：**Proposed（层 1 待 D2 拍板；层 2/3/4 属本批已做的 D0/D1）**。本件由刀㊶ 新开，起因是同一天早先那把刀（刀㊵）在账面里写下了一条**根本没被任何取证件回答过**的读数，而每轮都跑的门禁对此毫无反应。

## 1. 目标与非目标

**目标**（一句话）：让「这条读数是几点、几点取的、由哪个件取的」变成**机械可核对**的，并把产生这个读数的物理成因（三台节点每天有一段「两套时间基」的窗口）压到可接受长度。

拆成四条可判的子目标：

- G-1 成因量到顶：不是「三台时间不一致」这一句，而是**为什么会不一致、不一致多久、谁纠正的、用什么纠正**。
- G-2 物理层的机制解落地为**可 apply 的配置件**（本批只出件与判据，apply 需 D2 拍板）。
- G-3 账面层的机制解：新增一条不变量——**新增行里的 ISO 时间戳必须能在取证件里 grep 到**，引不到即红。
- G-4 把「面禁件没跑 `make lint` 全集」这条同类洞装上齿（本批实踩：`make lint` 已红而门件全绿）。

**非目标**（写明不做，免得后人读成已防）：

- 不消除虚机暂停。暂停是环境事实，guest 侧收不到 resume 事件（见 §3.3），我们能改的只有**源**与**收敛窗口**。
- 不引入 chrony/ntpd。框架选型规则里 chrony 是成熟件，但本批的成因不需要它（需要的是配好源 + 缩短 poll），换 daemon 属扩大影响面，若 §7 的 U-1 判定为「timesyncd 不能 step」再议。
- 不改任何后端代码。本批入库面全是文档 + gitignored 量具。
- 不把 runbook 促成交付件：它仍住 gitignored 目录，这一条**登记为债**（§7 D-1），不在本批悄悄做掉。

## 3. 根因分析

### 3.1 成因链（四条同时成立才出这件事）

1. **虚机整段停用**。单调钟（kvm-clock）反推的 boot 是 10-08，而墙钟/内核日志的 boot 是 06-12 ⇒ 墙钟走过 145 天里，机器真正在跑的只有 26.7 天，**累计停用约 118 天**。`clocksrc = kvm-clock` 在本环境里随暂停**一起冻结**，所以暂停期间 guest 的墙钟也停着走 ⇒ 恢复瞬间，墙钟落后量 = 暂停时长。#2 那两枚小时级 Jitter 与 #8「按漂移要几百万天」共同排除漂移解释：**只有跳变能造出这个量级**。
2. **从未配置过时间源**（#4：timesyncd.conf 有效行只有 `[Time]`；#11：DHCP 也没下发）。于是用的是发行版 fallback 的公网源。
3. **公网源在当前链路间歇不通**（#10 rtt 240–274 ms、#12 超时 84/104 行）⇒ 恢复后的第一次成功对时不是必然发生。
4. **收敛窗口上限 34min 8s**（#4 `PollIntervalMaxUSec`）⇒ 即使一切正常，**恢复后最长约 34 分钟**才纠正。

四条合起来的后果：**每天早上开机后的约半小时内，集群同时存在两套时间基**。#13 就是它的现网形状——同一份 API 响应里，不同节点上的 kubelet 各按自己的钟盖章，差 14 小时 44 分。这不是「日志难读」，这是**任何跨节点的时间比较在这一窗口内都没有意义**。

### 3.2 账面成因（为什么我写进了一条不存在的读数）

刀㊵ 在 §40.4 行 4 写了「09:08 那轮三方 `date -u` = 241 `01:08:34Z` / 125 `01:08:36Z` / 126 `2026-11-03T10:28:55Z`」。**结论方向是对的**（慢钟属实，#14 独立成立），**但那组三方读数在全仓任何件里都不存在**：本批实物复核取到 `01:08:34` 在 .tmp-scratch 与入库文件里 **0 命中**（唯一存在的三方轮是 #15 那组 `01:47:36/37/37`）。

根因不是「我不小心」，是三条机制缺口：

- **写读数时没有任何一步把它对回件**。§40.1 的「逐格绑件」是我自愿写的表头，不是判据；§40.4 那一行不在这张表里，就没人管它。
- **门件对「时间戳」这一类量没有概念**。它判路径存在性、判反引号成对、判表格形状、判后端 0 行——都是形状；内容里一个 ISO 时间戳是不是真的被谁取到过，不在射程内。
- **面禁件的命令集不是 `make lint` 的超集**。本批实踩：`make lint` 现在 rc=**1**（刀㊵ 把裸主机名写进两份入库文档，撞上公开镜像 registry 模式），而门件 B 格四道全绿——因为 B 格手抄了 4 条命令，与 `make lint` 的 5 条**各自漂移**。这跟 AGENTS.md《架构决策原则》说的是同一件事：**靠每个调用点"记得跑"就是散点式**。

### 3.3 为什么不能靠「暂停/恢复钩子」治

guest 收不到 hypervisor 的暂停事件（#16 显示只有 timesyncd 一份对时器、没有第二套；#7 显示连单调钟本身都跟着冻），所以任何「resume 时立刻校准」的方案都要求我们控制 hypervisor 侧——那超出本仓射程，属环境管理面。我们射程内只有：**源换成内网低时延 + 把收敛窗口压短**，以及**把「这一刻三台的钟可能不可比」变成读数前的强制判断**（§5 层 2）。

## 5. 迁移策略（四层，缺一层就还是散点）

**层 1 · 单一实现（物理成因）** —— 唯一定义处是一份 drop-in，三台同一内容，不在每台手敲：

```ini
# /etc/systemd/timesyncd.conf.d/10-intranet-source.conf
[Time]
NTP=<internal-ip>
FallbackNTP=ntp.ubuntu.com
PollIntervalMaxUSec=2min
```

`<internal-ip>` 是网关（真值住运维机本机 .intranet/keymap.json，仓内不写字面网段，口径见 lint_public_mirror 的「全仓零基建真值」注释）。配套三件都要有才算可执行：**apply 件**（写 drop-in + `daemon-reload` + `restart systemd-timesyncd`）、**rollback 件**（删 drop-in + 同上重启）、**复取件**（读回 `NTPSynchronized` / `ServerName` / `PollIntervalMaxUSec` / 新的 `Timed out` 行数）。⚠ 层 1 **本批不 apply**（D2）；§7 U-1 是它的前置。

**层 2 · 全局装配（现网链条里由构造保证不漏）** —— 白天链条第 0 步固定跑 k42-clock-audit.sh（三台各自跑，不让驱动机自己的钟参与），产出一格判决：

> `CLOCK-BASE-SPLIT`：三台 `date -u` 极差 > 2 s，**或**任一机 Jitter > 1 s ⇒ 本轮所有相对时间型读数（`AGE` / `Xm ago` / `--since` / 跨节点时间戳比较）**一律不入账**，只记「未取到 + 原因」。

它装配在 runbook 第 0b 步（本批已把闸门写进该件；那份 runbook 住 gitignored 目录 ⇒ 促成交付件属 §7 D-1），不是「记得就跑」。

**层 3 · 强制门禁（拦未来漂移）** —— 新增 ts-provability.ps1，判据三条，都由门件绑定判决：

- 新增行里的每个 ISO-8601 `T` 形时间戳，必须能在 corpus（gitignored 取件 + 入库件）里原样 grep 到，否则 `UNPROVABLE-TS`；
- 新增行引用到的取件名（形如 `kNN-*.txt`），必须真的在位，否则 `ARTIFACT-NOT-ON-DISK`；
- corpus 取不到（目录不存在/为空）⇒ `TS-CORPUS-EMPTY`，**fail-closed，不退回"当作没有"**。
- 另加对账格：门件 B 格的命令集必须 ⊇ `make lint` 的目标内容，缺一条即 `GATE-SET-MISSING`。

**层 4 · 闭环留痕** —— 本件的物理成因进 runbook 与坑表；「编造读数」这一型进坑表 + 装成门件齿；「门件命令集与 make lint 漂移」进 AGENTS.md 的取证规矩；`journalctl -u etcd` 读空当零进坑表（#9 实物）。

## 6. 验收标准（逐条可核，五字段：判据 / 期望 / 实取 / 定性 / 件）

1. **齿能咬**：往台账种一条假 ISO 时间戳 → 新格必须报 `UNPROVABLE-TS` 且门件 rc=1；字节还原后必须回到 rc=0。（不是口头声称，当场跑）
2. **齿不空转**：四枚合成自测（假戳必咬 / 真戳必放 / 非 ISO 形不误伤 / corpus 空必 fail-closed）全中才算上线。（实取已扩到 **七枚**：本刀又被自己的失败顶出三枚 —— native stderr 不杀工具、内容闸门双向、非空申报面；方向是加严不是放宽，逐枚名字与一条自犯在取证件 §41.1 行 2）
3. **对账格有效**：在补入 `lint_public_mirror` 之前，对账格必须已经能把这条漏报照出来（本批实取：`GATE-SET-MISSING: lint_public_mirror`）。
4. **`make lint` 回绿**：遮回两处裸主机名后 `uv run python scripts/lint_public_mirror.py` rc=**0**，且 P-4 违规项 = 0。
5. **层 1 的交付物存在且不被误读**：本件含 drop-in + apply/rollback/复取三件的形状与期望读数；账面任何位置**不得**出现「时钟问题已解决」，只许出现「成因已量到顶、配方已备好、apply 待 D2」。
6. **订正可核**：§40.4 行 4 的读数换成实物载体后，引用它的人按 §7 复跑口径能重取到同值。

**本件六条的逐条对账（实取值 + 绑件 + 定性）在取证件 §41.1**；量具自己那两处「瞎」的定性与处置在 §41.2 / §41.3，扫描面与命令面在 §41.4，上面验收 #4 为什么要改记「提交后复取」在 §41.5（同一节末段还记了本刀后半程怎么把这一格从「取不到」做成「问得出」：门件基准换成索引树 + 两道 fail-closed + 一枚假 ref 齿）。**本件不得单独作「验收已过」的陈述载体** —— 只有台账里那些带件名的读数才算。

## 7. 未证项 / 债 / 临时缓解（写明，不静默）

- **U-1（层 1 的前置，未证）**：残留的大偏差到底是被**谁**、**用什么方式**消掉的。可证的事实是：14h39m 的差在「真实时间约 01:09Z（由 #14 的件 mtime 折算，非原文）」与 `2026-11-04T01:47:36Z`（#15 原文）之间已经没了，**上界 39 分钟，与 `PollIntervalMaxUSec=34min 8s` 同量级** ⇒ 收敛窗口就是纠正延迟的直接因变量（这条决定层 1 有效）。但「timesyncd 是 step 还是 slew」本批**未判定**：我第一次用的 grep 串 `System clock wrong by` 是 ntpd/chrony 的文案而非 timesyncd 的，那格的 0 属**量具错**（已登记，不进任何结论）。判定路径：读本机 systemd 版本的 timesyncd 行为 + 一次可控实验（把钟设偏再 restart 观察），后者会把节点钟短暂弄错，属 **D2**，需人批。**在 U-1 判定之前，层 1 的全部有效性都是假设**。
- **D-1（债）**：白天链条的 runbook 仍住 gitignored 目录 ⇒ 换机即失、后人无法复跑。促成交付件要过脱敏与 doc-sync，是独立的一刀，不在本批悄悄做。
- **缓解声明**：本批对物理成因的实际处置是**「已量清 + 配方待批 + 判据已装」**，不是「已修」。三台节点明天早上仍会有一段时间基分裂窗口，只是我们现在**知道**它有上界并会在第 0 步照出来。
- **盲区声明（本格不防什么）**：ts-provability 只拦 ISO-8601 `T` 形。`2026-11-04 10:46:47` 这类空格形、`14 h 39 m` 这类差值、以及「把真实读数引错对象」都不在它射程内。它防的是特定一类（凭空的时间戳），不防全部，账面不许把「齿齐了」读成「取证内容全防住了」。
- **零豁免与它的代价（写清，免得后人当成漏洞）**：本格**没有**「推导项」免检口子。代价是：由别的量算出来的时刻（如 #14 折算出的 01:09Z）如果写成 ISO 形就会被判红。处置不是给齿加白名单，而是**账面改写为「带操作数的界限」**——操作数（件 mtime）与上界原文各自可核，推导这一步由读者能重算的形式表达。反过来，若哪天真需要口子，那必须是一次显式的判据换形（带自测与反证），不是悄悄加一条例外。

## 8. 复跑口径（引用本件任何读数前）

- 本件所有现网值绑取数时刻 2026-11-04 上午（UTC 02:0x–03:1x），载体为 #2–#17 各行末尾的件名。**件是 gitignored 的本机产物** ⇒ 换机或清盘后需重跑量具复取，不能引本表数字当现值。
