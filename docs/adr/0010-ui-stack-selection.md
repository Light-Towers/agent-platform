# ADR-0010: 界面选型（只读控制台扩展 / 独立前端工程）——决策记录

- 状态：**未决（本文不替用户拍板）**；它是 roadmap #18「无用户界面」的前置决策
- 日期：2026-10-16
- 来源：roadmap `plan-production-delivery-roadmap-2026-10-09.md` 阶段3 #24「3 项技术选型悬置」之三

## 1. 现状（先纠正一个容易说反的事实）

**"完全没有界面"这句话不准确**：仓内已有一处服务端渲染的**只读控制台**——

| 件 | 位置 | 规模/性质 |
|---|---|---|
| 路由 | `applications/agent_server/api/console_router.py` | 39 行 |
| 页面 | `applications/agent_server/static/console.html` | 343 行 |
| 测试 | `applications/agent_server/tests/test_console_router.py` | 在册（agent_server session 122 passed 内） |

同时：**全仓没有任何 JS 前端工具链入库**——`git ls-files` 对 `package.json` / `vite` / `tsconfig` / `*.jsx` / `*.tsx` / `*.vue`
**零命中**（本轮实测）。⇒ 真实的选择题不是"有没有界面"，而是**"要不要为界面引入一套前端工程与构建链"**。

## 2. 未决的是什么

| 选项 | 做法 | 代价 / 风险 |
|---|---|---|
| **A 扩现有只读控制台**（服务端渲染 + 原生 JS） | 在 `console.html` / `console_router.py` 上加"提问 → 执行 → 展示过程与结果 → 错误提示"的交互面 | ① 零新工具链、零新部署面（镜像已含该路由）；② 复杂交互（流式渲染、断线重连、状态回溯）全靠手写，代码会长在应用里；③ 与 #18 判据「不新增后端专用接口」天然相容 |
| **B 新建独立前端工程**（Vue3/React + 构建产物静态托管） | 起 `web/` 工程，走现有 HTTP/SSE 接口 | ① 引入 Node 工具链 + 构建步骤 + CI 面（本仓现为纯 Python uv workspace，`make ci` 无 JS 段）；② 部署清单要改（镜像多一层或另起静态服务）；③ 收益是可维护的交互复杂度与组件复用 |
| **C 混合：A 起步、把 B 作为重启后的演进** | 先用 A 打通一条完整业务链路并留证据，触发条件满足再迁 B | 需明确"什么时候必须转 B"，否则会变成永久 A（见 §4） |

判据侧的硬约束（不是我加的，是 roadmap #18 自己写的）：**「一条完整业务链路真跑通，留截图与日志；不新增后端专用接口」**
⇒ 无论选 A 或 B，都只能消费现有对外接口；若发现必须新增接口，那是**契约变更**，要另立方案并按「边界」规则先审计消费方。

## 3. 否决理由（已被证据关掉的判断）
- **「先做前端框架选型再说」**：本轮实测显示仓内没有任何 JS 工具链，选 B 等于同时引入**工具链 + CI 段 + 部署面**三件事，
  不是换一个 CSS 框架那么轻；在选 B 之前必须先回答"谁维护这套构建"。
- **「已有控制台 ⇒ #18 已满足」**：不成立。`console_router.py` 是**只读**性质，#18 要求的是可发起一条业务链路并展示过程，
  这条判据目前没有任何证据。⇒ 别把"有个页面"当成"有界面能力"。

## 4. 重启条件（选 A 时也必须认这几条）
1. 交互需求出现**流式渲染 + 会话回溯 + 多步过程可视化**三者叠加 ⇒ A 的手写成本超过 B 的引入成本，必须转 B。
2. 界面对象从"内部演示"变成"外部用户自助使用"（要登录态、可访问性、错误恢复） ⇒ 必须转 B。
3. 任一版本要在页面上做前端构建产物发布 ⇒ 必须先把 Node 工具链与 CI 段落进 `make ci` 的口径里（现在没有）。

## 5. 待用户回答
- A / B / C。选 B 还需给一句"前端框架与谁维护"（本仓技术栈规则要求只用成熟框架，且框架抽象须与需求契合）。
- 定了之后我按 roadmap #18 的改法走：**先出方案评审（含技术选型），再实现最小可用版**，不直接动手。
