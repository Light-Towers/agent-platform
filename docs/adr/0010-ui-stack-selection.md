# ADR-0010: 界面选型（只读控制台扩展 / 独立前端工程）——决策记录

## 1. 现状（先纠正一个容易说反的事实）

**"完全没有界面"这句话不准确**：仓内已有一处服务端渲染的**只读控制台**——

| 件 | 位置 | 规模/性质 |
|---|---|---|
| 路由 | `applications/agent_server/api/console_router.py` | 39 行 |
| 页面 | `applications/agent_server/static/console.html` | 343 行 |
| 测试 | `applications/agent_server/tests/test_console_router.py` | 在册（agent_server session 122 passed 内） |

同时：**全仓没有任何 JS 前端工具链入库**——`git ls-files` 对 `package.json` / `vite` / `tsconfig` / `*.jsx` / `*.tsx` / `*.vue`
**零命中**（本轮实测）。⇒ 真实的选择题不是"有没有界面"，而是**"要不要为界面引入一套前端工程与构建链"**。

## 2. 未决的是什么

| 选项 | 做法 | 代价 / 风险 |
|---|---|---|
| **A 扩现有只读控制台**（服务端渲染 + 原生 JS） | 在 `console.html` / `console_router.py` 上加"提问 → 执行 → 展示过程与结果 → 错误提示"的交互面 | ① 零新工具链、零新部署面（镜像已含该路由）；② 复杂交互（流式渲染、断线重连、状态回溯）全靠手写，代码会长在应用里；③ 与 #18 判据「不新增后端专用接口」天然相容 |
| **B 新建独立前端工程**（Vue3/React + 构建产物静态托管） | 起 `web/` 工程，走现有 HTTP/SSE 接口 | ① 引入 Node 工具链 + 构建步骤 + CI 面（本仓现为纯 Python uv workspace，`make ci` 无 JS 段）；② 部署清单要改（镜像多一层或另起静态服务）；③ 收益是可维护的交互复杂度与组件复用 |
| **C 混合：A 起步、把 B 作为重启后的演进** | 先用 A 打通一条完整业务链路并留证据，触发条件满足再迁 B | 需明确"什么时候必须转 B"，否则会变成永久 A（见 §4） |

判据侧的硬约束（不是我加的，是 roadmap #18 自己写的）：**「一条完整业务链路真跑通，留截图与日志；不新增后端专用接口」**
⇒ 无论选 A 或 B，都只能消费现有对外接口；若发现必须新增接口，那是**契约变更**，要另立方案并按「边界」规则先审计消费方。

## 3. 否决理由（已被证据关掉的判断）
- **「先做前端框架选型再说」**：本轮实测显示仓内没有任何 JS 工具链，选 B 等于同时引入**工具链 + CI 段 + 部署面**三件事，
  不是换一个 CSS 框架那么轻；在选 B 之前必须先回答"谁维护这套构建"。
- **「已有控制台 ⇒ #18 已满足」**：不成立。`console_router.py` 是**只读**性质，#18 要求的是可发起一条业务链路并展示过程，
  这条判据目前没有任何证据。⇒ 别把"有个页面"当成"有界面能力"。

## 4. 重启条件（选 A 时也必须认这几条）
1. 交互需求出现**流式渲染 + 会话回溯 + 多步过程可视化**三者叠加 ⇒ A 的手写成本超过 B 的引入成本，必须转 B。
2. 界面对象从"内部演示"变成"外部用户自助使用"（要登录态、可访问性、错误恢复） ⇒ 必须转 B。
3. 任一版本要在页面上做前端构建产物发布 ⇒ 必须先把 Node 工具链与 CI 段落进 `make ci` 的口径里（现在没有）。

## 5. 待用户回答
- A / B / C。选 B 还需给一句"前端框架与谁维护"（本仓技术栈规则要求只用成熟框架，且框架抽象须与需求契合）。
- 定了之后我按 roadmap #18 的改法走：**先出方案评审（含技术选型），再实现最小可用版**，不直接动手。

## 6. 决策（2026-10-29 落地）

- **用户原话**："行，那就最终定Vue"（2026-10-29）。选型文档 §7 已就 A/B/C 给出答案 **C**，本次拍板把框架项一并定下 ⇒ §5 两问均关闭。
- **选 C 的依据不是偏好，是本文 §4 自己的重启条件命中**：本批需求同时含流式渲染 + 会话回溯 + 多步过程可视化（`/query` SSE 13 类事件 + `/history` + `/session/revert`），按 §4 条件 1 原文"A 的手写成本超过 B 的引入成本，必须转 B"。⇒ 决策可追溯到本文预先写下的触发条件，不是新开判断。
- **§5 第二句的执行口径已满足**："先出方案评审"= 选型文档（三轮判据）+ 实施件（决策完备的工单表）；"再实现最小可用"= 实施件 PR-0..PR-4，**尚未开工**。
- **§6 阶段表的执行序：守 A 取证，且 A 步零代码改动**（2026-10-29 同日两次修正：先撤销"取消 A 步骤"，再撤销"A 步要补 revert"）。开工时曾按本文 §2 选项 A 的表述去 `console.html` 补 `/session/revert`（+76 行），跑该页在册测试 **2 条红**后全量回退（现 `git diff` 为空、`test_console_router.py` 12 passed）。两条实测事实：**① roadmap #18 判据四步不含"回退"**（原文＝提问→执行→展示过程与结果→错误提示，`docs/plans/plan-production-delivery-roadmap-2026-10-09.md:94`）；**② 只读控制台不得出现任何写入口**，这条由 `applications/agent_server/tests/test_console_router.py:22` 以 `_FORBIDDEN_ENDPOINTS` 钉住，依据是 **1.2 基线 6**（运维动作不进浏览器）。⇒ 本文 §3 那句"#18 目前没有任何证据"否的是**没证据**而非**没功能**：**取证动作本身即可关 #18，零代码改动**；§2 选项 A 那行"与 #18 判据天然相容"至此得到实证。
- **选型文档的两处源头已就地订正（本文不重写选型文档，仅记账）**：其 §0 第 1 条与 §4.2 P0 行原写"缺的只是 `/session/revert` 交互""补 revert 按钮"，根源是把 `docs/TODO.md:95` 给**新前端**列的复用接口误读成取证必做环节。订正后：P0 零代码、revert 归 `web/`；而 PR-3 另受一个**实测新缺口**前置——`checkpoint_id` 在现有对外接口里取不到（`RevertRequest.checkpoint_id` 必填 vs `/history` 与 SSE 各帧均不携带），详情与处置见实施件 §11.5。
- **§3 硬前置"谁维护这套构建"的答案**：维护 = 后端/数据团队 + AI 辅助（选型文档 §7 既有答案，本次未推翻）；契约层由 OpenAPI 生成托管，人只维护视图层。
- **§4 条件 3 的口径分歧裁决**：条件 3 与选型文档 §6 风险表（同口径另见其 §4.4 门禁表）均写"必须把 Node 工具链与 CI 段落进 **`make ci` 的口径**"。本批裁决为**只进 GitHub workflow 的 JS 段，不扩 `make ci`**。理由：`make ci` 必须在无 Node 环境可用（126 宿主无 Node、Windows 本机无 make，AGENTS.md 明文），扩进去会让后端改动的本地门禁在两类环境直接不可执行。⇒ 这是**对原要求的范围收窄而非遗漏**；若日后要 `make ci` 覆盖前端，须先解决无 Node 环境的旁路。（本行原写"选型文档 §10"为**错锚**：该文档最大编号到 §8，风险表在 §6。2026-10-29 交付前自检实取改正——与实施件 §11.4 记的"路径存在 ≠ 锚点存在"同型，这次是**别名存在 ≠ 锚点存在**。）
