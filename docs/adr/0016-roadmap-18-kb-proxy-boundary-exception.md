## 1. 问题

方案件 §6 刀 2 行（`:146`）要新建两个 agent_server 代理端点：`POST /kb/uploads`（D7）、`PATCH /kb/{knowledge_id}/status`（§4 feature 表 `kb.upload` / `kb.publish` 的消费点）。它们是**为 `web/` 上传页新增的后端接口**，而 roadmap #18 的完成判据逐字写着「不新增后端专用接口」。方案件 §8 P6（`:229`）判定「与字面相抵不是解释空间问题」，评审 #21（`:302`）把「补不补 ADR」升级为「刀 2 开工前置」。

本件要回答的不是「要不要写 ADR」（已拍），而是：**这条纪律的射程、两个端点是否算「后端专用接口」、以及取哪一立场**。

## 3. 待裁定的三个命题

1. **射程**：#18 只管「#18 取证批」（ADR-0010:52「零代码改动即可关」），还是覆盖 Phase 3 产品化（选型件 `:90`「延续 #18 纪律」、`:92` 触发条件已成立）？后者直接覆盖刀 2。
2. **定义**：消费 KS 现有接口、服务端断言 tenant 的**代理端点**算不算「后端专用接口」？若算，是否属 ADR-0010:30 的「契约变更」？「专用」二字给它留了窄解释空间（不是给界面单造一套数据模型，而是转发 + 断言），但该解释不能由实现批自决。

### 裁定（2026-11-12；依据用户批示「全局治本，但又不过度设计，优先核心内容」）

取 **乙的最小形态 = 射程裁决**，不做规则换代工程。上表三立场保留作证据，**甲与丙不取**。

1. **#18 结案，不改写原文**：`plan-production-delivery-roadmap-2026-10-09.md:94` 是阶段 3「最小可用版界面取证、10 人/日」的验收判据；`ADR-0010:52` 已定性「取证动作本身即可关 #18，零代码改动」，`readings.md:16` 只剩「真跑通待放行（模型密钥）」半格 ⇒ 它**不是被违反，是被越界引用到产品化阶段**。roadmap 原文与 `ADR-0010` §1–§5 一律不动。
2. **误延伸句以本件裁决覆盖，不连锁改文档**：`plan-frontend-stack-selection-2026-10-27.md:90`「延续 #18 纪律」是当时未区分语境的顺手延伸。按本仓「原文保留 + 追加订正」惯例与 `ARCHITECTURE.md:44`「ADR 不改写原则」，**不改该件**，由本件声明其射程读法以本件为准 ⇒ 避免「改 4 份在册件 + 索引」的过度设计。
3. **产品化边界 = 一条可判定口径，不是一套新规则**：为界面消费**现有子服务接口**而加的**服务端断言租户代理层**，不属于 #18 所禁的「后端专用接口」。四条同时成立才合规：(a) 服务端断言 tenant，body 自报值不参与归属（D20/R5）；(b) 经 HMAC 内部签名头转发、不直连子服务（D7）；(c) 不新建独立数据模型、不绕过断言层；(d) 转发目标为 KS/nl2sql 等既有入口，大小与生命周期校验仍落下游单一真相源（P11）。刀 2 两端点、刀 3 `datasources` CRUD（方案 `:102`）、刀 4 `GET /users` / `PATCH /users/{id}/role`（方案 `:217`）**按同一口径判，不再逐刀开例外**。
4. **防扩张复用已有护栏，不新增 lint 齿**：D20/D7/R5 反证、`P15` 签发符号窄门禁、C5 端点成对性、`applications/agent_server/tests/test_console_router.py:22` 路径集恒等已在册；§7 复审触发兜住新形状。⇒ 不新立接口治理规则、不新增齿（那是换代工程，超出「优先核心内容」）。

**不取甲的理由**：刀 3 / 刀 4 的新端点会反复撞同一条纪律，例外清单无限增长且无收口条件 —— 与 `ADR-0014` 那种「heads 回到 2」的一次性例外不同型。**不取完整治本的理由**：改 `ADR-0010` + 选型件 + 方案件 + docs 索引并新增齿会牵动在册引用链、需重跑全套取证，属过度设计；本裁定用**一份件**达到同一防复发目的。

⚠ 本裁定**仍未放行 2a**：KS 镜像重建+分发（方案 §6 刀 2 前置）与 Q6 现网取证仍待执行 / 人批，不得把「ADR 已决」读成「已获批准开工」。
