# ADR-0014: PR-0 视觉层工作线 `feat/web-visual-poc` 转正为唯一集成分支（远端 heads 由恒 2 改为恒 3 的知情例外）

- 状态：**已决并执行（2026-11-02 用户拍板）**
- 日期：2026-11-02
- 来源：`docs/plans/plan-web-frontend-minimal-core-2026-10-29.md` §8.1 第 3 条那句长期挂着的「（b）依旧是 D2 未执行项」，在第十七批收盘时被明确要求收口
- 关联：`docs/adr/0012-nl2sql-branch-consolidation.md`（分支收敛与删死枝的先例）、`docs/operations/branch-hygiene-monthly-checks.md`（月度体检的读数与命令面）、`AGENTS.md`《分支卫生》

## 1. 现状与问题

《分支卫生》写的终态形态是「远端恒 2 分支：`main` + 唯一集成分支」，工作分支短命、PR 合回后本地与远端当场删。2026-11-02 现取（命令与逐值在 `docs/operations/evidence/2026-10-30-web-visual-references/readings.md` §25.2）：

| 对象 | 实测 |
|---|---|
| `git remote` | 两条：`company`（内网 GitLab，真实工作仓）+ `github-legacy`（公开脱敏镜像，pushurl 被写成禁用串）。**无 `origin`** |
| `company` heads | **3 条** = `main` @ `fe22794c` / `feat/web-visual-poc` @ `0b4c1f37` / `lineage/intranet-v3-until-2026-10-19` @ `12f03c8f` |
| `company/main` 与本工作线 | **异宗**：`HEAD..company/main` = 2，merge-base 为空 ⇒ 不能快进合并，要合只能改写远端历史 |
| 本地 `main` | `88515cab`，与 `github-legacy/main` **同一个 sha** ⇒ 本地 `main` 是公开遮敏树，不是内网工作线 |
| 工作分支 | **一条也没切过**。第十七批收盘累计 22 刀全部直接落在 `feat/web-visual-poc` 上（切点 `d140f91f`，第八批拍板） |

⚠ **本表是第十八批的现取快照，不是现值**：同日第十九批把刀㉓ 补推上远端（`company/feat/web-visual-poc` tip 从 `0b4c1f37` 变为 `c9622fdc`），并按下面 §5 第 6 条**退役删除了本地旧工作线**（远端从未有它，heads 仍 3 条）。引用本表前先复跑 `git ls-remote --heads company` 与 `git for-each-ref --format='%(refname:short)' refs/heads`。

⇒ 差距不是「多了一条分支」，而是**角色缺失**：这个仓的视觉层工作从来没有「集成分支 + 从它切出的短命工作分支」这一层，`feat/web-visual-poc` 事实上一直在承担集成分支的职责（所有刀的父提交链都在它上面，远端也只有它承载这些内容）。把它当工作分支去「PR 合回 + 删枝」，需要一条**并不存在的**第二条分支做回退目标。

## 2. 决策

**用户 2026-11-02 拍板：`feat/web-visual-poc` 转正为本仓视觉层/V3 工作线的唯一集成分支；`company` 远端 heads 在本阶段按 3 条登记为知情例外，并同步修订计数口径。**

三条构成这个决策的语义：

1. **集成分支角色认定**：`feat/web-visual-poc` 就是「唯一集成分支」。后续工作分支（PR-1 起）从它切出、PR 合回它、合完当场 `git branch -d`（本地与远端都删）。**不再新建** `int/` 之类的第二条集成分支。
2. **计数口径修订**：《分支卫生》那句「远端恒 2 分支」的计数维度是「工作分支」，**不含历史锚 ref 与公开镜像侧载体**（后者由该文件第 5 条单独算）。因此本仓的合规形态是 `main` + 唯一集成分支 + `lineage/*`（锚）= **3 条 heads**；月度体检第 2 步的「>2 报警」读数命中 3 时，指向本件而不是自动算违规。
3. **`company/main` 保持不动**（同日另一问的批示）：异宗历史 + 需改写远端 ⇒ 属不可逆项，不得由实现批自决。合入 `main` 仍须用户显式批示，且届时要先给异宗处置方案。

## 3. 后果

- 正面：账面与实物一致。「22 刀都在同一条线上」从一处需要解释的偏离，变成一条有角色定义的常态；每刀的父提交链、远端 tip、取证 rev 三者天然对齐（第十七批的推送读数就是这种对齐的产物：`4d34e656..0b4c1f37` 一次快进即覆盖两刀）。
- 代价：本仓在 PR-0/PR-1 期间**没有**「工作分支 < 24h 短命」这条保护。所有刀直接进集成分支 ⇒ 出错只能在集成分支上回退，回退面比小 PR 大。缓解 = 每刀收盘仍跑门禁件 + `e15-postcommit`，并把形状数（files/add/del）记在提交信息里，回退时按刀次定位。
- 不变的部分：《分支卫生》第 1、2、4、5 条对本仓继续全额生效；「合入 `main` 须用户显式批示」继续生效；公开镜像 `github-legacy` 的 pushurl 禁用位不因本件解除。

## 4. 备选方案（为何不选）

- **(b′) 新建内网集成分支 `int/…` 并首推，然后把 `feat` 并进去、当场删 `feat`**：多一次**不可逆的远端删枝**，且 22 刀的提交信息、17 批台账、月度体检文件里所有以 `feat/web-visual-poc` 为坐标的读数全部失去指向（要重写历史引用）。为「形式上回到恒 2」付出的代价是把已证住的取证链拆掉。
- **(c) 维持现状只挂账、不写本件**：违反《分支卫生》第 2 条 —— 没有复审触发条件的登记不许写，而无登记的挂账正是 ADR-0012 §42 那条「禁删未带条件 ⇒ 死枝供成两个月」的同型错误。
- **(d) 把 `feat` 当成工作分支、另找集成分支（本地 `main`）**：本地 `main` = `88515cab` = 公开遮敏树，**第八批已明令不得从它切**；拿它当集成目标会把公开镜像的形状引进内网工作线。

## 5. 复审触发条件（命中任一条即重新决策，不得等「以后再看」）

1. **出现第二条并行工作分支** ⇒ 从 `feat/web-visual-poc` 切出、PR 合回、当场 `git branch -d`（本地 + 远端）。这是本件认可的正常形态，不构成例外扩张。
2. **视觉层具备合入条件**（PR-1 验收过 + 用户批示）⇒ 一次性处理 `feat` → `company/main` 的异宗问题：先出方案（保留 `main` 快照线 as-is / 以 merge 提交显式连接 / 改写公开历史）再动手，不得直接 force。
3. **`lineage/intranet-v3-until-2026-10-19` 的退役结论被确证**（该游离线在别处已可获得或不再需要锚定）⇒ 删该 ref，heads 回到 2，本件 §2 第 2 条的计数口径随回。
4. **月度体检**（`docs/operations/branch-hygiene-monthly-checks.md` 命令面第 2 步）实取 heads **> 3** ⇒ 当周处理，不允许「先记着」。
5. **本件例外超过一个季度未复审**（下一个触发点 = 2027-02 之前的月度体检任一节）⇒ 即便上面四条都没命中，也要重跑 §1 那张表并明确「继续例外 / 收口」。
6. **旧工作线 ref 已被本件的角色认定取代** ⇒ 它于 2026-11-02 按《分支卫生》#1 以 `git branch -d` 退役（三列读数全命中：cherry `+` = 0・独有文件 = 0・是集成分支祖先；过程读数与逐值在 `docs/operations/branch-hygiene-monthly-checks.md` 的「2026-11-02 步 3 补跑节」）。后果：**该分支名不再解析**（`git rev-parse --verify` rc=128），而 `docs/` 下有 38 处取证坐标以它为名字。两条口径由此定下：① 历史取证台账里的分支名**不回填**（那是当时的实物），复跑时改用当时登记的 sha（`d140f91f` / `896f966e`，两者实测仍在 HEAD 祖先链上）；② **不得为了让旧命令能跑而重立同名 ref**——那会把一条已退役的线供成「看起来还在」，比死枝更坏。触发复审 = 发现任何 commit 只存在于那条线上（`git log --all --not HEAD` 非空，或某 sha 只在公开镜像树里）⇒ 从镜像侧 fetch 回来重立并推翻本条。
