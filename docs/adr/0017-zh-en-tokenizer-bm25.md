## 1. 结论先行

三条检索链路的词法能力统一为：**引擎侧 BM25（Milvus 内置 Function）+ jieba 分词器 + 领域词典单源**；dense 路保持不变；手写正则分词与本地近似稀疏向量分阶段退役。

三条硬边界：

1. **词法由引擎生成**：应用侧不再预计算并传入稀疏向量，也不再手写正则切词。BM25 稀疏向量由 Milvus Function 从原文生成。
2. **单一实现 / 单一装配**：两个 Python 服务共用 `agent-runtime` 的共享分词模块（optional extra 声明 `jieba`，遵守 `applications → agent-runtime → agent-core` 单向依赖），唯一入口 `get_tokenizer()`；禁止服务内自建分词函数、正则切词或词典读取逻辑。
3. **行为等价门禁，而非版本号门禁**：同一批混排样本在三侧（引擎侧用临时集合实测）产出词项集合必须相等；注入配置或词典不一致时门禁 rc≠0。配套架构不变量 lint 禁止本地分词实现。两把门禁各只保留一把并入库、自证能咬。

**不升级 Milvus 服务端**：本批保持 v2.5.10（已具备 BM25 Function 与 jieba tokenizer）；现网引擎大版本升级、存量 `platform_doc_v3_bge_m3` 兼容验证与服务端级回退另立工单 / ADR。

## 2. 为什么这么选

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 稠密 + 应用侧 BM25（`rank_bm25` + 手写 bigram） | 否 | 中文字符 bigram 不是分词，领域词边界靠猜；三处各自实现，无法保证一致 |
| B. 稠密 + learned sparse（BGE-M3 sparse / api 模式 md5-TF 近似） | 退役 | 通用模型对领域型号 / 缩写不稳；导入端与查询端编码不一致会让稀疏路 IP 恒 0 且静默退化（已有事故记录） |
| C. 稠密 + Elasticsearch BM25 | 否 | 新增一套引擎与运维面，违反"不引入第三套检索栈"；Milvus 已具备原生 BM25 |
| D. `language_identifier` 自动路由中英分析器 | 否 | 整段文本判一种语言、选一个分析器；短中英混排查询（如 `HAK-180 烫金机怎么用`）会丢掉英文词项边界 |
| **E. 稠密 + Milvus 引擎 BM25 + 单一 jieba + 领域词典** | **采纳** | 官方示例证明 jieba 可在同一串上保英文整词并切中文词典词；引擎生成稀疏向量消掉应用侧一致性风险；单一实现 + 单一装配 + 行为门禁符合 AGENTS.md 全局解三层判据 |

英文词干化（stemming）明确不做：领域召回以型号 / 术语精确匹配为主，语义相近由 dense 路承担；如确有需要，另设双 analyzer 双 BM25 通道 + RRF，属独立决策。

## 3. 后果

### 3.1 正面

- 手写正则分词在检索读点归零，领域词由词典保证完整；中英混排不再"判一种语言"。
- 稀疏编码一致性风险从应用侧转移到引擎侧；旧 canary 退为历史读件，新门禁按行为等价判定。
- 三个服务共用一份实现与一份词典 / 配置源，"靠人记得改三处"变为构造保证 + 门禁兜底。

### 3.2 代价与约束

- analyzer 在建集合时固定：变更必须新建集合 + 双写 / 重灌，不能热变更；旧集合保留至少 14 个自然日且跨一次完整部署窗口。
- `agent-runtime` 增加 optional extra（`jieba`）；nl2sql-service 需新增对 `agent-runtime` 的依赖，须复核依赖图与镜像安装清单。
- 英文词干缺失是有意权衡，不是已解决问题。
- 两份新量具（行为等价门禁、架构不变量 lint）必须先入库并自证能咬，否则退化为约定。

### 3.3 可逆性

- 集合版本化 + 双写 + 灰度切换 + 10 分钟内集合 / 配置层回退；引擎面故障不属本批回退范围。
- 本 ADR 判 D1：AI 给方案与证据，人批准实施；`main` 未被直接提交。

## 4. 复审触发条件

出现任一情形即主动复审本 ADR，不等下一轮人工发现：

1. POC 证明 v2.5.10 上 jieba 自定义词典无法注册，或 hybrid search 的 BM25 腿不能传原文。
2. 领域 golden case 显示词法路 recall@5 / recall@10 相对基线回退，或融合后指标回退。
3. 行为等价门禁对注入的不一致连续两次未咬（rc=0），或架构不变量 lint 对合成违规未咬。
4. 决定升级 Milvus 到 3.0 或更高（引擎面变化触及本 ADR 的版本边界）。
5. 需要英文词干化 / 双 BM25 通道（触及本 ADR 明确放弃的备选 E 扩展）。
6. 方案件或两把量具从版本控制清单消失，或只住在本机 gitignored 目录。
7. **（2026-11-26 T2 POC 实测触发）** v2.5.10 不支持引擎侧自定义词典 / `run_analyzer`，方案曾退为"引擎内置 jieba + Python 侧 add_word"；**同日按用户要求把 POC 容器升到 v2.6.3 并挂载 local 领域词典，`run_analyzer` 已验证领域词整词切分，治本形态在 POC 成立**。代码以 `RETRIEVAL_ANALYZER_PROFILE` 分档，默认仍 `simple_2_5` 保住现网 2.5.10；切到 `domain_dict_2_6` 前须先完成现网引擎升级 + 回退预案并复审两侧行为等价判据。
